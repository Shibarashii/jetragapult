# Jetragapult — Dotfiles

Personal dotfiles for two CachyOS machines: **jetragon** (desktop, 2 monitors) and
**dragapult** (laptop). Managed with **GNU Stow**: each top-level dir is a stow
package mirroring `$HOME` (e.g. `hypr/.config/hypr` → `~/.config/hypr` is a symlink
into this repo). Editing files here edits the live config.

## Package map

| Package | Live path | Notes / deeper rules |
|---|---|---|
| `hypr` | `~/.config/hypr` | Hyprland **Lua** config — see `hypr/.config/hypr/CLAUDE.md` |
| `nvim` | `~/.config/nvim` | lazy.nvim config — see `nvim/.config/nvim/AGENTS.md` |
| `noctalia` | `~/.config/noctalia` | Shell/bar/launcher (Noctalia); Hyprland binds call `noctalia msg …` |
| `kitty` | `~/.config/kitty` | Terminal; `themes/noctalia.conf` is regenerated by Noctalia theming |
| `tmux` / `tmuxp` | `~/.config/tmux`, `~/.config/tmuxp` | tmuxp YAMLs are per-project session layouts |
| `fish`, `zsh` | `~/.config/fish`, `~/.zshrc` | fish is the login shell |
| `yazi` | `~/.config/yazi` | File manager |

## Commands

- Stow a package: `cd ~/Jetragapult && stow <pkg>` (dry run: `stow -nv <pkg>`)
- There is no build or test suite. Verification is per-tool (see each package's rules file).

## Conventions

- Commit messages: Conventional Commits (`feat:`, `fix:`, `refactor:`, `chore:`), scoped optionally (`fix(colorscheme): …`).
- One logical change per commit; don't bundle unrelated packages.
- Config must work on **both** machines — branch on hostname/device, don't hardcode one machine's hardware.

## Boundaries

- **Never** commit secrets, tokens, or machine-local state (`fish_variables`, plugin dirs — see `.gitignore`).
- **Never** run `stow -D`, `stow --adopt`, or delete/move package dirs without asking: it breaks live symlinks.
- **Ask first** before installing packages or adding plugins.
- Generated files (`kitty/themes/noctalia.conf`, `nvim/lazy-lock.json`) often show as modified. Leave them out of unrelated commits.
